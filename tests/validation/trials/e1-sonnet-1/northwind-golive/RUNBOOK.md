## Handover note

**What changed, and why** (Northwind onboarding, WFM-nnn tickets as referenced):

- *Config.* New `configs/northwind.yaml` carries the SOW: three queues, 30-minute grain, America/Chicago,
  the SOW §1.2 targets (priority 90/30, standard 80/20, vip 90/20), the 0.85 occupancy cap, the 0.95 weekly
  attainment bound, the 06:00-24:00 vip floor of one agent, and the scheduling rules. `configs/defaults.yaml`
  is unchanged; every key is client-specific and opt-in, so Contoso and Fabrikam run as before.
- *Ingest.* Northwind's export is local time with an explicit UTC offset per row. The loader used the
  wall-clock label (and could not read 2026-11-01, where 01:00-02:00 occurs twice); it now derives UTC from
  `utc_offset`, builds the week from its elapsed length (338 intervals in 2026-W44: 25-hour Sunday) and
  reads the `vip` queue. Rows off the 30-minute grid (two 10:01 rows in 2026-W44) are placed in the
  interval they fall in; duplicates, missing intervals and negative volumes are cleaned and reported on stderr.
- *Staffing.* `aht_smoothing: interval` was accepted but not honoured (the queue mean was always used); it now
  uses each interval's own handle time. The occupancy cap (WFM-212) is applied when a client sets
  `enforce_occupancy_cap: true`, which Northwind does. Erlang C is `wfm/staffing/erlang.py`; no abandonment.
- *Scheduling.* New `wfm/scheduler/weekly.py` (selected by `scheduler: weekly`) plus `wfm/scheduler/search.py`:
  week-aware placement with 11 h elapsed rest, split shifts only for PT, elapsed-hour caps, the 5-day run
  limit, VIP cover in every interval 06:00-24:00, breaks 2-5 h into the shift in the interval of largest
  gross surplus, and a local search over the whole roster because day-by-day placement leaves weekends
  without agents. `wfm/scheduler/greedy_v2.py` (WFM-231) was not used: its rest test is inverted.
  Existing clients still use `greedy.py`.
- *Evaluation and reports.* The evaluator counts every operating interval of a queue (vip: 08:00-20:00),
  audits rest, split-shift contract, break count/window/placement, and writes `required_hours`.
  This file and `exceptions.md` are generated by `wfm/report.py`.

**SOW §2.8 - pre-existing deviations from the §1 method that affect Northwind's queues:**

- `aht_smoothing: queue_mean` (WFM-198, service default) replaces each interval's handle time with the
  queue mean; §1.2 requires the interval's own handle time. Northwind overrides it.
- The occupancy cap is read from config but was never applied in required staffing (WFM-212); §1.3 requires it.
  Northwind opts in; the other clients are unchanged and are still staffed without it.
- The service default targets (80/20 for priority and standard, `sla_target` 0.90) differ from the SOW;
  Northwind overrides them. The service default break rule (shift midpoint) and split-shift eligibility
  (everyone) also differ from §2.2/§2.3; Northwind overrides both.
- The vip queue was not known to the ingest, and its local-time conversion mishandled the DST change.
- Not affecting Northwind (own config, not inherited): Fabrikam's `queueing: qlib` (abandonment, library
  default patience 90 s since qlib 1.3) and `attainment_basis: coverage`, and Contoso's temporary
  `sla_target: 0.72`. Fabrikam's fixed-offset export table (WFM-204) is also wrong for the hours before the
  change on a DST date.
